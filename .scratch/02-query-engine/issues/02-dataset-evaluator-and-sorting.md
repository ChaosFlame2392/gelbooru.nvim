## Answer

Implemented `matches(post, plan_or_query)` and `evaluate(posts, plan_or_query)` in `lua/gelbooru/query/engine.lua`:
- `engine.matches(post, plan)` validates a post against the criteria generated by `engine.prepare`:
  - Positive tags, negative tag exclusions, and tilde/pipe OR disjunction groups against post tags, artist, character, and filename stem.
  - Normalized rating matches and exclusions with support for single-letter aliases (`g`, `s`, `q`, `e`) and multi-rating commas/pipes.
  - Score relational comparisons (`>`, `>=`, `<`, `<=`, `==`, bare), resolving score from cached disk metadata if unhydrated.
  - Artist, character, and ID filtering.
- `engine.evaluate(posts, plan)` executes in-memory dataset transformations without mutating input arrays:
  - Filters posts against criteria matching rules.
  - Sorts posts by `score`, `id`, `date`/`mtime` (ascending/descending), with deterministic tie-breaking on post ID descending and file URL ascending.
  - Implements Fisher-Yates shuffle for `sort:random` / `order:random`.
  - Sequentially applies pipeline stages, slicing ranges (`start..finish`, `start..`, `..finish`) and limit/offset windows.
- Verified with 59 test cases in `tests/unit/query_engine_spec.lua` and full test suite passing cleanly with 0 failures / 0 errors.
